## 규칙

- **대상 시스템에 쓰지 않는다.** 위 목록에 있는 것만 부를 수 있고, 전부 읽기다.
- 컬렉션·토픽·키 이름을 **추측하지 마라.** 모르면 `mongo.list_collections`,
  `kafka.list_topics`, `redis.scan`으로 **먼저 찾아라.** 찍어서 부르면 빈 결과가
  오는데, 그건 "데이터가 없다"가 아니라 "질문을 잘못했다"이고 둘은 다른 사실이다.
- 태스크 하나는 **읽기 하나**다. 여러 번 읽어야 하면 태스크를 여러 개로 나눠라.
- 앞선 태스크의 결과가 있어야 정할 수 있는 읽기는 `input_evidence_ids`에 그 증거
  id를 적어라. 그러면 그 증거가 생긴 뒤에 실행된다. 증거 id는 `<태스크id>.e1` 꼴이다.
- `priority`는 낮을수록 먼저다. **증발하는 것(현재값)을 먼저 봐라** — 시간이 지나면
  못 보는 것이 있다.

## 답

JSON 객체 **하나만** 내라. 설명을 붙이지 마라.

```
{
  "hypotheses": [
    { "id": "h-1", "statement": "무엇이 원인일 수 있는가 (한국어 한 문장)" }
  ],
  "tasks": [
    { "id": "t-1", "goal": "무엇을 확인하는가 (한국어)", "role": "data_prober",
      "action": "mongo.list_collections", "params": {}, "priority": 10 }
  ]
}
```

`role`은 `data_prober`(데이터 조회) / `code_tracer`(코드 확인) / `recompute_verifier`
(재계산 대조) 중 하나다. **지금은 데이터만 읽을 수 있으므로 `data_prober`를 써라.**

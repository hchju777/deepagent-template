# 6a단계 — 케이스 개설과 게이트

> **목적**: finding이 케이스가 된다. **같은 문제로 케이스가 쌓이지 않는다.**

```bash
python -m src patrol list                          # 어느 점검이 어느 주기로 도는가
python -m src patrol open --all-sites --dry-run    # 열릴 케이스를 보여만 준다
python -m src patrol open --all-sites              # 실제로 연다
python -m src case list                            # 열린 케이스
python -m src case show c-1
```

```
$ python -m src patrol open --gbm mx --fct gumi
🆕 c-1    mx/gumi  Operator/Check       Operator/Check — 전부 0 — alarm·caution·normal이 모두 0이다
🆕 c-2    mx/gumi  Material/ATR Status  Material/ATR Status — 전부 0 — ...

$ python -m src patrol open --gbm mx --fct gumi          # 3시간 뒤
↻  c-1    mx/gumi  Operator/Check       2회째 · 3시간 0분째
↻  c-2    mx/gumi  Material/ATR Status  2회째 · 3시간 0분째
```

## 왜 무시가 아니라 **첨부**인가

3시간마다 도는데 문제가 안 고쳐지면 케이스가 **하루 8개** 쌓인다. 그렇다고 그냥
무시하면 "언제부터 이랬나"가 아무 데도 안 남는다.

첨부하면 케이스가 `관측 4회 · 9시간째`를 들고 있다. **"지금 0/0/0이다"와 "9시간째
0/0/0이다"는 다른 사실이고**, 후자가 조사와 보고서의 재료다.

첨부는 **처음 본 값을 안 덮는다.** 케이스가 든 것은 열릴 때의 근거이고, 나중 값으로
덮으면 왜 열렸는지가 사라진다.

## 지문이 문자열이 아니라 튜플인 이유

```python
Fingerprint = tuple[str, str, str]     # (site, check, target)
```

`f"{site}|{check}|{target}"`이 짧고 보기 좋은데, **`target`에 구분자가 들어갈 수 있다.**
`target`은 대상 응답의 필드를 이어 붙인 것(`"Line/Target Rate"`)이라 우리가 고르지
않은 문자열이고, 언젠가 `|`가 섞이면 서로 다른 두 대상이 같은 지문으로 접힌다 —
**케이스 하나가 조용히 사라진다.**

튜플이면 이스케이프 문제가 아예 없다. 저장소가 작아서(사이트 28 × 점검 몇 × 대상
몇십) 선형 탐색으로 충분하다.

## 닫힌 케이스를 되살리는 유일한 조건

조사가 끝나 케이스가 닫혔는데 여전히 0/0/0이면 3시간 뒤 또 열린다 — 같은 조사의 반복이다.

> **닫힌 뒤 그 대상이 한 번이라도 정상으로 관측돼야 다시 연다.**

그게 "새 사건"의 정의다. 대가는 정직하게 적는다 — **안 고쳐진 문제는 다시 안 알린다.**
사람은 이미 보고서를 받았으니 알고 있다. "미해결이 N일째"를 상기시키는 경로가 없는
것은 [backlog ①](backlog.md)과 같은 계열이고, 12b의 보고서가 그 자리다.

### "정상으로 관측됐다"를 어떻게 아는가

`CheckOutcome`이 **판정한 대상 목록**(`targets`)을 싣는다. finding 목록만으로는
"정상이었다"와 "응답에 아예 없었다"를 못 가른다. 후자는 *"빠진 것은 검사 대상이
아니다"*라 정상이 아니고, **그걸 정상으로 치면 닫힌 케이스가 잘못 되살아난다.**

`skipped`·`unreachable`은 **아무것도 하지 않는다.** 판정을 안 했거나 못 했으므로
정상도 이상도 관측되지 않았다 — 둘 중 어느 쪽으로도 상태를 움직이면 안 된다.

## 순찰은 케이스를 닫지 않는다

`note_clear`는 **닫힌 케이스에만** 적는다. 순찰이 정상을 봤다고 조사가 끝난 것은
아니다 — 케이스를 닫는 것은 조사(12a)이지 순찰이 아니다.

## 대상을 다시 읽지 않는다

케이스에 싣는 값은 finding이 **판정 시점에 본 것** 그대로다. 게이트가 어댑터를 인자로
받지도 않는다. 통과 시점에 다시 조회하면 그 사이 값이 바뀔 수 있고, 그러면 보고서가
"0/0/0이라 열었다"는데 케이스엔 다른 값이 실린다 — 읽는 사람이 그 모순을 만나면
시스템 전체를 안 믿게 된다.

## 저장소 — 깨진 파일을 **조용히 비우지 않는다**

읽다 실패하면 "케이스가 하나도 없다"로 떨어지고 싶은 유혹이 있다. 그러면
**열린 케이스를 전부 잊고 다시 연다.** 게다가 닫힌 케이스도 잊으므로 "이미 조사한
것"이 되살아난다. 조용히 틀리는 쪽이다.

그래서 던진다. 게이트가 `rejected`로 흡수하므로 순찰은 안 죽고, 사람은 "케이스가
안 열린다"를 출력에서 본다.

**쓰기는 원자적이다** — 임시 파일에 쓰고 `os.replace`. 쓰는 도중에 죽으면 원본이
반쯤 덮여 깨지는데, **그게 바로 위의 "깨진 파일"이다.** 우리가 직접 만들어 놓고
다음 순찰에 못 읽는 꼴이 된다. `os.replace`는 Windows에서도 원자적이다.

## 주기는 **점검마다**

```json
"badge_all_zero": { "interval_minutes": 180, ... }
```

전역 하나로 두면 무거운 점검이 생겼을 때 전체를 그것에 맞춰 늦추게 되고, 가벼우면서
중요한 점검까지 같이 느려진다. 지금은 `patrol list`가 읽어 보여 주고, **실제로 그
주기로 도는 것은 6b**다.

### 승급 폴링을 안 쓴 이유

"처음 발견되면 짧은 주기로 전환해 N회 확증"을 검토했다. 평상시 부하와 확증 속도를
분리한다는 발상은 맞는데, **우리 숫자로는 고정 짧은 주기가 더 빠르고 단순하다** —
승급이 빠르게 만드는 것은 확증이지 발견이 아니고, 발견이 전체 지연의 대부분이다.
그리고 순찰이 대상마다 주기를 갖게 되어 9g 스케줄러의 "겹치지 않음을 구조로 보장"이
깨진다. 자세한 것은 [decisions ⑬](decisions.md).

## 검증

방어를 하나씩 지워 **전부 실제로 RED를 봤다**:

| 지운 것 | |
|---|---|
| 첨부(항상 개설) | 2 failed |
| 닫힌 뒤 억제 | 1 failed |
| 지문의 `target` / `site` | 3 / 1 failed |
| 관측값 없으면 거부 | 1 failed |
| 게이트 무raise | 1 failed |
| `skipped`·`unreachable` 가드 | 1 failed |
| 안 본 대상을 정상으로 안 치기 | 1 failed |
| 깨진 파일을 안 비우기 | 2 failed |
| 원자적 쓰기 | 1 failed |

### 그 과정에서 내 테스트 둘이 거짓 초록이었다

- **`skipped` 가드**: 빈 outcome으로 검사하고 있었다. 움직일 것이 애초에 없으니
  가드를 지워도 통과한다. `targets`와 `findings`를 실어야 가드가 보인다.
- **원자적 쓰기**: "임시 파일이 안 남는다"만 봤다. 곧장 덮어쓰는 구조도 임시 파일을
  안 남긴다. `os.replace`를 실패시켜 **원본이 멀쩡한지**를 봐야 한다.

둘 다 RED를 만들어 보지 않았으면 못 찾았다.

## 여기까지 오면

```
순찰이 이상을 찾는다  →  케이스가 열린다  →  [멈춤]  →  조사  →  판정  →  메일
     ✅ 4·5단계            ✅ 6a                      10b~11    12a     12b
```

**케이스가 열릴 뿐 아직 조사되지 않는다.** 지금 돌릴 수 있는 것은 `case dryrun`(대본)뿐이다.

## 검토 포인트

1. **`case_store` 파일이 프로세스보다 오래 사는가** — 공유 드라이브인지 컨테이너
   안인지에 따라 재시작 의미가 달라진다. backlog ④와 같은 질문이다.
2. **동시 쓰기.** 지금은 프로세스 하나를 전제한다. 6b의 데몬과 사람이 손으로 돌리는
   `patrol open`이 겹치면 마지막 쓰기가 이긴다.
3. **케이스가 닫히는 경로가 아직 없다.** 12a가 생기기 전까지 전부 `open`으로 쌓인다.

→ 다음: 6b — 점검별 주기로 순찰 데몬에 올린다. 실행 순서는 [로드맵](step-00-overview.md).

### 대상 환경의 규모 — **사이트 28개**

리포에 든 `config/registry.json`은 자리표시자 둘(`mx/gumi`, `mx/sevt`)이지만
**사내 실제는 28개다.** 이 숫자가 순찰(4·5·6)과 워커(14)의 설계를 정한다:

- 3분 주기면 하루에 **28 × 480 = 13,440 사이트-라운드**다. 중복 케이스 게이트(6단계)가
  "있으면 좋은 것"이 아니라 **없으면 못 돌아가는 것**이 된다.
- 28개 중 하나쯤은 매일 안 붙는다. **"못 봤다"가 예외가 아니라 일상 경로다**
  ([decisions ⑪](decisions.md)).
- 조사 하나가 LLM 라운드 여러 개라 분 단위다. 여러 사이트에서 동시에 케이스가 열리면
  **큐가 실제로 밀린다** — 14단계의 lease·keepalive가 장식이 아니다.

**모양**: 사업부 4개이고, 사업부마다 사업장 집합이 다르다 — 곱집합이 아니라
들쭉날쭉하다. 그리고 **한 사업장에 사업부가 둘 있을 수 있다**(SEV에 MX와 NW).
그래서 `registry.json`이 쌍을 명시 열거한다. 용어는 [decisions ⑩](decisions.md)에 —
"법인"은 사람마다 다른 것을 가리켜서 단위 이름으로 쓰지 않는다.

일일 리포트는 **28개 전부를 돌고 있다**(사내 확인 완료).

### 먼저 여기서 돌린다 — `tools/local_case.py`

```bash
.venv/bin/python tools/local_case.py --root output/local-case     # 측정판을 만든다
# 찍힌 두 명령 중 첫째(investigate)를 돌리고, output/local-case/turns/NNN-ask.md 가
# 생길 때마다 리드 대역(haiku 에이전트 등)이 NNN-reply.md 를 써 준다. 둘째(trace)로 요약.
```

하네스를 고쳤으면 **사내보다 먼저 이걸 돌린다.** 같은 배선(CLI → 리드 → 그래프 → 트레이스)
이고 리드 자리만 파일 턴이다. 심은 고장은 sink 컨슈머 정지 하나, 이름은 전부 지어낸 것.
사내 실행은 마지막 확인 한 번이면 된다.

### 사내 실행 결과를 넘길 때 — `case trace`

```bash
python -m src case investigate <케이스id> --trace ./trace
python -m src case trace <케이스id> --trace ./trace --brief   # 이 출력만 옮기면 된다
```

`--brief`는 "이미 물은 것"·"예시가 보여준 것" 줄을 뺀다 — 둘 다 코드에서 다시 만들 수 있다.
**전체 pytest는 사내에서 돌리지 않아도 된다.** 고치는 쪽이 여기서 돌린다(스위트·RED 스윕).
사내에서 확인할 것은 위 두 명령뿐이다.

트레이스 원본은 라운드당 수천 자라 사람이 옮길 수 없다. 그래서 지금까지 **진단
요약만** 건너왔고, "리드가 무엇을 보고 무엇을 뱉었는지"는 한 번도 안 건너와서
매 라운드 원인을 코드에서 역추적했다 — 그게 왕복의 진짜 원인이었다.

`case trace`는 라운드마다 이것만 찍는다: 프롬프트 **크기(블록별)**, **우리 판정**(`결과:
읽었다` / `못 읽었다 — 사유`), 리드가 본 것의 **건수**, **이미 물은 것**, **예시가 보여 준
것**, **가설·결정**, **리드가 낸 것**(+ 예시와 같은 모양인가 · 증거에 없는 이름인가 · 이미
한 질의인가). 못 읽은 응답은 크기와 앞머리만. 같은 라운드의 두 번째 블록은 `(재시도
N회째)`(JSON을 못 읽어 다시 물음) 또는 `(거부 뒤 다시 물음)`(코드가 태스크를 버려서 그
자리에서 되물음)이다. 증거 **내용은 안 찍고**(대상 config에 비밀이 있을 수 있다) 비밀처럼
생긴 인자 이름의 값은 가린다.

## 합의된 작업 방식 — 이게 제일 중요하다

이 리포의 CLAUDE.md 규율에 **더해서**, 이 프로젝트에서 사람과 합의한 것들이다.

### 진행 방식

1. **작업 전에 알린다**: 목적 · 손댈 파일 · 무엇을 테스트할지.
2. **작업 후에 알린다**: A/M/D 파일 목록.
3. **한 단계 → 리뷰 요청 → 수정 → 다음 단계.** 한 번에 여러 단계를 하지 않는다.
4. 큰 판단(설계가 갈리는 지점)은 **먼저 묻는다.** 되돌리기 어려운 것은 특히.
5. **후속의 후속을 만들지 않는다.** 후속은 (a) 방금 낸 것의 버그이거나 (b) 그 단계의 종료 판단에
   필요한 것일 때만. 나머지는 backlog에 적고 다음 단계로 간다. 단계를 시작할 때 **종료 판단이 무엇인지
   먼저 적는다** — 11d 6c-2에서 후속이 넷까지 간 뒤 합의한 것(10-05).
6. 대상 코드에 대한 **사실**이 필요하면 먼저 "도구가 찍어 줄 수 있는가"를 본다 — 못 찍으면 그게 만들
   기능이다. 사람에게는 **판단**만 묻는다("이 경로가 실제로 돌 수 있는가"). 사내 코드를 열어 읽어 달라는
   질문은 결국 사내 사례에 규칙을 맞추는 길이다(decisions ⑮).

**전체 RED 스윕과 그 뒤의 기계적인 커밋·푸시는 Fable이 아니라 더 싼 모델(sonnet/haiku 서브에이전트)이 돈다**(10-08 합의).
Fable은 결과(RED 수·초록/자리 못 찾음·트리 상태)만 받는다. 앵커 재지정처럼 판단이 필요한 것은 서브에이전트가 손대지 않고
돌려준다. 스윕을 돌리기 전에 앵커 사전 검사(`CASES`의 old가 소스에 정확히 한 번 있는지)를 Fable이 먼저 한다 — 두 번
연속으로 스윕 끝에서야 "자리 못 찾음"을 보고 재지정 커밋을 따로 냈다.

### 언어

- 코드 주석·문서: **한국어**, WHY만(식별자가 이미 WHAT을 말한다).
- git 커밋 메시지: **영어**.
- 식별자: 영어.
- 모델 이름(Claude/Opus 등)을 커밋 메시지·PR·코드 어디에도 넣지 않는다.

### 검증

- **"고쳤다"는 자체 판단을 보고하지 않는다.** 실제 소비자로 확인한다 — 렌더러로
  렌더해 보고, CLI를 실제로 돌려 보고, 파일을 열어 본다.
- **RED → GREEN을 실제로 둘 다 확인한다.** 새 테스트를 쓰면 소스를 일부러 깨서
  그 테스트가 **정말 실패하는지** 본다. 이 프로젝트에서 "테스트는 초록인데 아무것도
  안 지키고 있던" 사례가 여러 번 나왔다(아래 함정 참고).
- **환경을 고쳐서 만든 초록은 증거가 아니다.** 11a에서 첫 명령으로
  `git config --global protocol.file.allow always`를 켜고 그 위에서 전부
  통과시켰다. 개발 트리는 늘 초록이고 사내에서만 깨졌으며, 원인을 찾는 데
  세 라운드가 갔다. 전역 설정·환경변수·`~/.gitconfig`를 건드렸다면 **되돌리고
  다시 재라.**
- **재현이 먼저다.** 원인을 짐작해서 고치지 마라. 못 재현하겠으면 고치지 말고
  **실패가 스스로 말하게** 만들어라(아래 참고). 11a에서 짐작으로 고친 라운드가
  두 번 있었고 둘 다 헛일이었다.
- **픽스처는 실물과 같은 모양이어야 한다.** 손으로 비슷하게 만들면, 그 차이가
  어느 플랫폼에서 어떻게 드러날지 아무도 모른다. 그리고 픽스처는 **자기
  결과를 확인해야 한다** — 안 그러면 "세웠다고 믿었는데 아니었다"가 세 단계 뒤의
  엉뚱한 assert로 나타난다.
- **테스트가 부르는 보조 명령의 실패는 원문을 들고 죽어야 한다.**
  `subprocess.run(..., check=True)`의 `CalledProcessError`는 종료코드만 말하고
  stderr를 삼킨다. 남의 기계에서 깨졌을 때 사람이 그걸 타이핑해 옮기게 된다.
- **포슬린에 판정을 걸지 마라.** `git submodule status` 같은 상위 명령은 플랫폼마다
  깨질 자리가 많다. 같은 사실을 `git config`처럼 낮은 명령으로 읽을 수 있으면
  그쪽을 쓴다.
- 전체 테스트는 `.venv/bin/python -m pytest tests/ -q`.

### 보안·안전

- **API 키를 대화에 붙여넣지 않는다.** `.env`에만 있고 그건 gitignore다.
- 비밀이 아닌 것(모델 ID, 수신자, api_base)은 **config에** 둔다 — git에 있어야 리뷰된다.
- **TLS 검증을 전역으로 끄지 않는다.** `ssl._create_default_https_context` 치환,
  `REQUESTS_CA_BUNDLE`, 세션 몽키패치 전부 금지. 필요하면 그 커넥션 하나에만.
- 대상 시스템에 **완전 읽기 전용**. 포트에 쓰기 메서드를 만들지 않는다.
- **사내 호스트명·계정을 이 GitHub 리포에 넣지 않는다.** `config/`의 값은
  자리표시자(`redis://h:6379`)로 둔다.
- 프롬프트에 접속 정보가 섞이지 않는지 본다(테스트가 지킨다).

### 사내 트리로 옮기기

**파일 단위로 복사하지 않는다.** 실제로 버전이 섞여서(옛 테스트 + 새 소스) 하루를
날린 적이 있다. `git archive`로 통째로 옮긴다 — 절차는 [README](../README.md)의

## 이 프로젝트에서 실제로 깨졌던 것들

CLAUDE.md의 "흔한 실수"에 더해, 9단계에서 새로 나온 것들이다.

### 초록불이 아무것도 증명하지 않았던 세 번

1. **`pytest.ini`가 live 테스트를 걸러낸다.** `addopts = -m "not live_llm and not
   live and not live_mail"`. 걸러진 테스트는 **수집은 되지만 호출은 안 된다** —
   `build_prompt`를 필수 인자로 바꿨을 때 `tests/live`의 세 호출부가 그대로
   남았는데 "678 passed"였다. 사내에서 `-m live_llm`으로 돌린 사람이 발견했다.
   → 시그니처를 바꾸면 **전수 확인**이 필요하다. 초록불은 증거가 아니다.
2. **테스트가 자기가 쓴 파일을 자기가 읽었다.** 프롬프트 기본 경로 테스트가
   파일 이름을 두 번째로 적어 두고 있어서, 스키마 기본값이 바뀌어도 초록이었다.
   → `tests/config/test_schema_report.py`가 이제 스키마에서 이름을 가져온다.
3. **`ScriptedAdapter`가 예외를 응답으로 바꿔 준다.** 그래서 `comment_on`의
   최외곽 try/except를 지워도 대본 테스트 27개가 전부 통과했다.
   → 방어를 검사하려면 **실제로 던지는** 짝이 따로 필요하다.

### 11a에서 **내가 만든** 실패 넷

대상 코드 확보(11a)에서 사내 실패가 네 라운드 이어졌다. 넷 중 셋은 제품 코드가
아니라 **내 작업 방식**이 원인이었다.

1. **검증 환경을 내가 고쳐 놓았다.** `protocol.file.allow=always`를 전역으로 켜고
   그 위에서 통과시켰다 → 그동안의 "전부 통과"가 전부 무의미했다.
2. **픽스처가 환경 능력에 기댔다.** 로컬 경로를 `git submodule add`로 붙였는데
   그건 git 2.38.1부터 막힌 유일한 명령이다. 내가 만든 문제를 막는 코드를 두
   라운드 덧댔다. `.gitmodules`는 파일이고 gitlink는 트리 항목이라
   **손으로 만들면 허락이 아예 필요 없었다.**
3. **픽스처가 실물과 다른 모양이었다.** submodule을 `clone` + `init`으로 채우니
   `.git`이 파일이 아니라 디렉터리가 됐다. Linux에선 같게 읽혔다.
4. **인코딩을 자식 프로세스에 적용 안 했다.** `tests/test_portability.py`가 이미
   같은 규율을 `open()`에 대해 갖고 있었는데 `subprocess`엔 없었다
   ([windows.md](windows.md) 함정 ①-b).

그리고 RED 스윕이 **거짓 초록**을 하나 잡았다: "config를 못 읽으면 안전하게
답한다"는 분기가 지워도 결과가 같았다 — 방어가 아니라 무동작이었다.

→ submodule 방어 25가지를 한 스크립트로 모아 **매 라운드 다시 돌린다.**

### 같은 버그가 **새 자리에서** 되살아난다

10b에서 "증거를 잘라 놓고 완전하다고 적었다"를 고쳤다. 11a에서 `code.config`가
큰 dict를 돌려주기 시작하자 **같은 버그가 `ProbeRunner`에서 다시 나왔다** —
`complete`를 어댑터 봉투에서만 가져왔고, 그 뒤 우리가 예산에서 자르는 것은
아무 데도 안 실렸다.

→ **자르는 곳이 새로 생기면 그 사실을 실어 보내는지 같이 확인하라.**
   "없다"와 "못 봤다"의 구별은 자르는 지점마다 다시 세워야 한다(⑪).

### config가 선언만 하고 아무도 안 읽던 것

`app.json`의 `timezone`이 그랬다. 스키마에 있고 기동이 검증까지 하는데 시계는 그
값을 **안 읽고** 시스템 TZ를 따랐다. 사내가 KST라 우연히 맞았다. 같은 규칙으로
훑으니 `output_dir`과 `per_gbm`이 더 나왔다.

→ `tests/config/test_dead_settings.py`가 이제 이걸 구조로 막는다. **새 config 항목을
추가하면 반드시 읽는 코드도 같이 넣어라.**

### 시간대

`datetime.now().astimezone()`은 그 기계의 시스템 TZ를 따른다. UTC 컨테이너에서
`0 8 * * *`은 **한국 시각 오후 5시**에 돈다. 집계 쪽도 같이 틀린다 — 화요일 아침에
돌면 "어제(직전 평일)"가 월요일이 아니라 **금요일**이 되고, 제목의 날짜도 같이
밀려서 **완전히 정상으로 보인다.**

→ 시계는 `_clock(args, env)` 하나뿐이고 `app.json`의 `timezone`을 읽는다.
`src/` 안에서 `.now()`를 직접 부르면 테스트가 잡는다.

### 대상 데이터

- **`occ_date`는 문자열이다.** 범위 비교가 사전순이라 형식이 고정폭·큰자리우선이
  아니면 조용히 틀린 구간을 읽는다. 기동이 막는다.
- 실제 값에 **소수 자릿수가 섞여 있다**(`00:00:00.011`, `00:00:00.545776`).
  `parse_formats`에 추가로 적어야 한다. 처음에 44,507건이 "형식 불일치"로 버려졌다.
- 알람 항목 이름 안에 **지시문처럼 보이는 문장**이 들어올 수 있다. 공격이 아니어도
  설비 메시지가 우연히 그럴 수 있다 → `fenced()`와 프롬프트 울타리, 그리고
  `problems()`의 한국어 검사.

### 메일 HTML

Outlook 데스크톱은 **Word 엔진**으로 렌더한다. 중첩 `<table role="presentation">` +
인라인 스타일만. `<style>`·`class=`·flex·grid·float·`@media` 전부 무시된다.
width/height/bgcolor/valign은 **속성으로도** 적는다. 인라인 SVG는 아예 안 보인다
(그래서 차트가 직접 만든 PNG다).

한국어는 기본적으로 음절 사이에서 줄이 바뀐다 → `word-break:keep-all` +
`overflow-wrap:break-word`, 그리고 U+00A0(문자 그대로, `&nbsp;` 엔티티가 아니다 —
`html.escape`가 이중 이스케이프한다).

### 사내 환경

- **사내 PyPI에 없을 수 있다**는 것을 계속 전제했다. matplotlib 대신 PNG 인코더를
  직접 썼고, croniter 대신 cron 파서를 직접 썼다. 새 의존성을 넣기 전에 이걸 먼저
  생각하라.
- 파이썬 3.11.3(사내)과 3.11.15(개발)의 **argparse 동작이 달랐다.** 표준 라이브러리의
  "이렇게 하면 되는" 트릭은 마이너 버전이 같아도 믿지 않는다.
- Windows에서만 터지는 것들은 [windows.md](windows.md)에 모아 뒀다.

## 열려 있는 것

[backlog.md](backlog.md)에 있고, 각각 **"왜 지금은 괜찮은가"와 "언제 문제가
되는가"**를 함께 적었다. 요약:

1. **실패가 사람에게 닿는 경로가 없다** — 상주 프로세스라 종료 코드가 안 나온다.
   지금은 "메일이 안 오면 사람이 안다"로 버틴다. 못 막는 건 **메일은 왔는데 반쪽인**
   경우다.
2. **발송 멱등이 없다** — 자동 재시도가 생기면 중복 메일이 된다.
3. 프로세스 감시 — 바깥의 몫.
4. `output/` 보관 — 한 번 만들었다 되돌렸다(`git revert`로 히스토리에 있다).
5. 순찰·조사(4·5·6·10~15단계) — **지금 여기를 시작한다.**
6·7. 사내에 물어봐야 답이 나오는 것들(langgraph 반입, graphify 심사).

**1·2는 사람이 "지금은 이대로 간다"고 명시적으로 판단한 것이다.** 빠뜨린 게 아니다.
**6·7은 코드로 못 푸는 것이다** — 사람이 사내에 확인해야 답이 나온다.

1. high 상한: 사내 출력이 여기 없어 제가 셀 수 없습니다. 아래 기준으로 세어 주세요.
- 이유: 검증은 두 사실(인용 증거 잘림, 인용 코드의 레포 ≠ component 레포)을 이미 알지만 caveat만 적고 확신은 안 깎습니다. 그래서 <작업자 케이스> 2회차 high가 그대로 나갔습니다.
- 셀 칸(최상위 원인 기준, external은 레포 칸 제외):
  - A-전부: 인용 증거가 전부 잘림
  - A-하나: 인용 증거 중 하나라도 잘림
  - B-전부: 인용한 코드가 전부 다른 레포(component 레포 코드 0건)
  - B-하나: 인용한 코드 중 하나라도 다른 레포
- 세는 법: 잘림은 conclude 트레이스의 "잘린 증거 N건" 줄과 인용 id를 맞대 봅니다. 레포는 출력의 "…은 레포 B의 코드다" caveat을 봅니다. 칸마다 맞은 high와 틀린 high를 나눠 주세요.
- 상한 후보는 B-전부→medium, A-전부→medium입니다. 맞은 high가 0건인 칸만 채택합니다("하나라도" 규칙은 안 씁니다).
- 다음 판부터는 판정 출력에 "검증 사실: 인용 잘림 a/b · 다른 레포 코드 c/d" 한 줄을 넣겠습니다(동작 변경 없음).

2. 유형만 세기: 만들겠습니다. 아래 다섯 가지를 확인해 주세요.
- (1) 상한 뜻: N건 창을 다 셌는데 0건이면 "비었다(일부)"로 나쁨입니다. T초·걷기 예산 소진·읽기 실패일 때만 "모름"입니다. 맞습니까?
- (2) 안전장치: 창에서 유형 칸이 든 메시지가 0건이면 "모름 — 유형 칸 <f>이 든 메시지 0건"으로 둡니다. 선언한 칸 이름이 틀렸을 때 "0건 → 나쁨"이라는 틀린 사실을 막기 위해서입니다. 멤버 값이 리터럴이 아닐 때도 모름입니다.
- (3) 리드 액션 인자는 {topic, class}만 받습니다. 셀 유형 값은 코드가 유형표에서 풉니다(LLM이 값을 대지 않게). 걷기가 같은 인자로 이미 냈으면 중복으로 반려됩니다.
- (4) 섞인 토픽 행 뒤 사다리 칸 kafka.tail을 이 액션으로 바꾸고, 이미 셌으면 칸을 비우겠습니다. 지금 tail 칸이 리드의 tail 반복을 부추깁니다.
- (5) 재생 시드: (가) 창의 메시지를 녹화하는 방식과 (나) 이 읽기의 결과를 인자별로 녹화하는 방식(REST captures처럼) 중 고르시면 됩니다. 저는 (나)를 권합니다. 세는 로직은 가짜 데이터 다섯 경우의 테스트로 지킵니다.

## 공통 원칙 (라운드마다 다시 확인)

- **코드가 먼저 한다.** 강한 모델이 스스로 하는 것(중복 차단·열린 질문·정체 감지·도구 결과 요약·예산)을 약한 모델 대신
  하네스가 한다. LLM은 "왜"만 판단한다(규율 6).
- **잘라서 보여 주지 않는다 — 골라서 전부 보여 준다.** 증거는 전부 저장(id)하고 프롬프트에는 고른 부분을 통째로.
- **사내 어휘는 리포에 안 들어온다.** 계보 관례(metadata 필드 이름·use 플래그 키), 컬럼·컬렉션 이름은 `knowledge/topology`
  와 config의 자리표시자로. 측정판 픽스처는 **모양만** 옮긴다(실명 제거).
- **닫힌 스키마.** 새 도구는 인자가 닫혀 있고(규율 9), 계산 도구는 연산 몇 개지 식 평가가 아니다.
- **역할별 LLM.** 액션 턴은 빠른 모델·작은 `max_tokens`, 판정은 생각하는 모델. 읽는 곳이 없는 역할은 미리 두지 않는다.
- **벽은 먼저 잰다.** 숫자(8K·30초·5분)는 트레이스의 `응답 N초`·첫 조각 초·프롬프트 크기를 보고 정한다.

## 사내에서 받아야 할 것 (R3 전까지, 전부 자리표시자)

1. 요약 키 값의 JSON 모양 — `metadata` 아래 필드 이름(쓴 파이프라인·바로 위 토픽·상태·생성 시각이 어디 있나).
2. 파이프라인 config에서 use 플래그가 놓인 자리(키 경로)와 GBM 기본·사이트 덮어쓰기의 예.
3. 배지 API 응답 한 행의 필드 이름(identity 필드 둘, 수치 필드 셋).
4. 원천 키 한 행의 필드 이름(문제의 두 컬럼 포함)과 그 키가 어떤 모양으로 저장되는지(목록? 해시?).
5. 코드 줄 둘: ① batch가 kafka 명령의 target_resource로 키를 **쓰는** 줄, ② 동적 키를 읽는 함수의 읽기 줄(키 조립식 포함).
6. R2-1 재측정의 일곱 줄 + `응답 N초`·첫 조각 초(스트리밍이 벽을 넘는지).

**R3-3 — 코드가 상류를 걷는다 (측정 #9, 앞당김. P0 1·2·3, P1 4·5·6·7).**

리드가 한 홉씩 걷는 구조의 한계가 드러났다 — 입구 노드의 고리(키 값의 잎 = 클래스 → `code.resources` → 입력)를 **코드가 키마다 반복**한다.

리터럴로 같이 있을 때만 나쁨(실측: `["<필드>"] != "-"` 줄과 554행 전부 `'-'`인 데이터가 일치), 나머지 단일값은 표시만. 멈춘 자리의 다음 홉은
그 리터럴 줄의 함수, 없으면 `_run`과 같은 문자열로 등록된 클래스 본문(`get("X")` ↔ `register(component="X")` — 호출 그래프에 없다);
원천(값의 잎 = 토픽 이름)에서 멈췄으면 그 토픽 lag/tail과 같은 이름의 수집기 클래스. 같은 클래스 이름이 두 레포면 **대상 키를 선언한 서비스**로
가른다(후보끼리 가를 때만, 표에 근거; 둘 다 선언이면 둘 다). 걸은 읽기는 State에 읽기마다 증거(판정이 인용한다), 프롬프트는 홉 표 + 나쁜 홉의
본문(행 요약), 걸은 읽기는 중복 집합에, conclude도 같은 구성.

**R3-5 — 고침만 (측정 #11). 원칙: 기능 동결, 한 판에 질문 하나, 틀린 사실보다 "모름".**

사람 결정(10-15): (1) 등록은 레포마다 **등록 모음 파일 한 곳**(데코레이터가 아니라 호출): (a) 한 줄 단순 이름 `register(component="X")(Cls)`가 대부분,
(b) 사이트 인자 `register(component="X", gbm=…, factory=…)(Cls)` — 같은 X가 사이트마다 다른 클래스(기본은 아무 것도 안 하는 클래스, 특정 사이트만 실제),
(c) 점 표기 `alias.Cls`(`import <모듈> as alias`), (d) 여러 줄 `register(...)(\n    Cls\n)`; 문서 문자열 속 `@register` 예시는 등록이 아니다 → **정규식이
아니라 AST**: `register` 호출의 `component` 상수 + 바깥 호출 인자(Name, 또는 Attribute의 끝 이름 — 별칭은 모듈). 사이트: 명시 인자 값이 전부 이 사이트
값과 같은 등록만 후보, 그중 명시 인자가 많은 것, 수가 같으면 여럿. 두 케이스의 사슬은 전부 (a)라 #12로는 (b)~(d)가 검증이 안 된다 → 측정판에 넣는다.
(2) 자원 0인 클래스도 파일에 `get("X")` 리터럴이 있다 — 단일값 없이 클래스 파일에서 링크를 뽑아 뒤 칸을 만든다. (3) `M` = 그 행의 **문자열** 단일값 수
(문자열 아닌 단일값은 "대조 안 함 K개"로 따로), `N` = 대조한 수; 상한을 없애면 `N<M`은 조회 실패 때뿐. 못 이은 컴포넌트가 하나라도 있으면 `N=M`이라도
"일부만"이고 멈춤도 `입력이 다 정상`이 아니라 `입력을 다 못 봤다`. 빈 배열에도 요약 `[value.record: 행 0]`. (4) `case walk`: 다른 명령처럼 `--gbm --fct`,
`--check` 필수(기본값 없이, 틀리면 점검 목록), `--target`은 순찰이 만드는 문자열(`"/".join(row[f] for f in identity)`) 그대로 — 행마다 같은 방식으로 이어
통째로 비교하고 쪼개지 않는다(제목에 `/`가 든 행이 있다). (5) 문구는 사실만: `나쁨 — 554행 전부 <필드>='-' · 이 필드 값이 든 비교식 <파일>:L<줄> '<줄 원문>'`.
"(값이 '-'인 이유는 위에서)" 같은 말은 넣지 않는다 — 코드가 원인을 말하게 된다. 위 홉에서 같은 값을 찾으면 그 행에 이미 `같은 단일값(아래 홉과 같다)`이 붙는다.

  재시도는 1회이고 프롬프트를 더 접어서(1-2), 시간 초과 뒤엔 안 한다(R1). `parallel_width`는 triage에서만. 대본(`dryrun`)
  형식 v2, `trace_digest`·`diagnose` 맞춤. `frame/select/execute/integrate`는 R4 끝까지 나란히 두고 벤치로 비교한 뒤 걷는다.
- **R4-3 도구**: 3-1 `code.grep` 전 레포 `레포:파일:줄 | 내용`, 개수 상한만; 3-5 `data.*` 닫힌 연산(`value_counts(field)`·
  `count(where)`·`filter(where)`)을 증거 id 위에서(표준 라이브러리, pandas 없음); 3-6 모든 결과에 id(이미 그렇다).
- **R4-4 실험(I)**: 네이티브 함수 호출 어댑터 옵션 — 게이트웨이가 받으면 JSON 수리 재시도가 준다. 사내 `llm check`로 확인 뒤 결정.
